# 题库数据约定（Question Bank Schema）

## 这个仓库是什么

更准确的称呼是：**离线题库复习运行时（study / quiz shell）**，外加一份**内嵌演示题库**。

| 层级 | 是什么 | 在哪里 |
|------|--------|--------|
| 运行时 | 答题、错题本、随机卷、相近题、AI 解析本地编辑、PWA 离线缓存、备份 | `site/*.html` 内的应用逻辑 + `src/` |
| 题库内容 | 章/节/考点 + 题目数组；当前仓库内嵌约 1028 道演示题 | `site/index.html` 中的 `allQuizDataInGroupedFormat` |
| 外部题库 | 用户通过「导入」替换/追加的 JSON | 不进 Git；符合下文约定即可 |

**内嵌题目不是“唯一真源”**，只是方便安装后立刻可练。真正要长期维护的业务题库，应以外置 JSON 为准，并在导入前用本仓库校验脚本检查。

常见做法是按**章（或大节）做成彼此独立的 JSON 片段**，分别导入叠加。每一片段仍须是完整合法的题组数组。
**给非开发作者的「怎么做题库、上传失败怎么办」**见：[authoring-question-bank.md](authoring-question-bank.md)（含导入器 `tryParse` 正则/答案拆字陷阱与排障清单）。

运行时对导入数据偏**宽松归一化**（中英文字段别名、缺省填“未分类”）；**并不等于**有完整的题目质量约束。作者侧约束见下文「严格规则」，并由 `npm run test:schema` 执行。

---

## 严格作者格式与运行时兼容格式

严格校验（默认 CLI 与 JSON Schema）要求：使用标准英文字段的非空**分组数组**；`chapter`、`section`、`topic` 是非空字符串；`q` 是非空字符串；`o` 是 2–26 个字符串；`a` 是无重复的大写 A–Z 字母数组，且答案必须在选项范围内；`type` 必须显式为 `single`、`multiple` 或 `judge`。案例只放组级，值为字符串、对象或 null。

运行时还兼容中文别名、扁平题目数组、字符串答案及部分题型别名。这些旧格式可用 `--lenient` 做结构提示，但**不属于严格作者格式**。宽松检查不会保证题目可正确判分，也不是导入 UI 的逐项复刻。

## 顶层形状

严格作者格式必须是**非空数组**，元素为「题组（group）」：

```json
[
  {
    "chapter": "第一章 …",
    "section": "第一节 …",
    "topic": "考点一：…",
    "caseInfo": null,
    "questions": [ { "…": "见题目对象" } ]
  }
]
```

运行时也支持**扁平数组**（严格校验不接受）（每项直接是题目）：导入时会被包成一组
`chapter=题库 / section=全部题目 / topic=人工校对`。
推荐作者始终使用**分组数组**，便于章/节/考点筛选。

中文别名（仅运行时兼容，严格校验请使用标准字段）：

| 标准字段 | 别名 |
|----------|------|
| `chapter` | `章` `章节` |
| `section` | `节` |
| `topic` | `考点` |
| `questions` | `题目` `题库` |
| `caseInfo` | `材料` `背景` `案例` |

## 题组（group）字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `chapter` | 严格必填 | 非空章名；运行时缺省 → `未分类` |
| `section` | 严格必填 | 非空节名；运行时缺省 → `未分类小节` |
| `topic` | 严格必填 | 非空考点；运行时缺省 → `未分类考点` |
| `questions` | **是** | 题目数组；至少 1 题（有 `caseInfo` 时运行时强制） |
| `caseInfo` | 否 | 案例/材料。**只能是字符串或单个对象**，不能是数组。属于组级，不要塞进小题 |
| `caseUid` | 否 | 案例稳定 ID；缺省由运行时生成并通过指纹注册表复用 |

运行时已有硬校验（`validateCaseGroups`）：

1. `caseInfo` 不得为数组（多段材料请拆成多组）。
2. 有 `caseInfo` 则 `questions` 不能为空。
3. 函数本身会检查小题内的材料字段；但当前导入链先经过 `normalizeQuestion`，这些字段会被丢弃，实际导入不一定报错。**严格作者校验会直接拒绝小题内的 `caseInfo` / `材料` / `背景` / `案例`**，防止材料静默丢失。

## 题目（question）字段

| 字段 | 必填（严格） | 说明 |
|------|--------------|------|
| `q` | **是** | 题干。别名：`题干` `question` |
| `o` | **是** | 选项数组。别名：`选项` `options`。元素为字符串 |
| `a` | **是** | 正确答案。别名：`答案` `answer`。见下文 |
| `type` | **是** | 严格用 `single` \| `multiple` \| `judge`；运行时另兼容 `多选题` / `判断题` / `truefalse` |
| `e` | 推荐 | 解析文字。别名：`解析` `explain` |
| `uid` | 推荐 | 稳定 ID；缺省生成 ID，再按章/节/考点/题干/选项指纹在本机注册表中复用；不是跨设备确定性哈希 ID。**学习记录、错题、AI 解析都挂在 uid 上** |
| `htmlContent` | 否 | 富文本题干 HTML |
| `number` | 否 | 展示用题号 |
| `qImages` / `optionImages` / `explanationImages` | 否 | 图片附件（见运行时 `normalizeImageList`） |
| `aiAnalysis` / `aiUpdatedAt` | 否 | AI 助教解析；本地编辑优先于导入旧值 |

### 答案 `a` 的写法

- 严格必填：无重复的**大写**字母数组，如 `["C"]`、`["A","C","D"]`。字母对应选项顺序 **A=第 1 项，B=第 2 项…**
- 仅运行时兼容字符串；会去掉中文逗号、顿号、分号和空白再按字符拆分，**不会去掉英文逗号**。字符串答案不通过严格校验。小写字母也不会自动转成大写，可能判错。
- **严格规则**：每个答案字母必须落在选项范围内（有 4 个选项则只能是 A–D）

### `type` 与答案数量

| type | 含义 | 严格约束 |
|------|------|----------|
| `single` | 单选 | `a.length === 1` |
| `multiple` | 多选 | `a.length >= 1`（推荐 ≥2；若只有 1 个正确项仍应显式标 `multiple` 仅当题干要求多选） |
| `judge` | 判断 | 选项通常为「正确/错误」两类；`a.length === 1` |

若省略 `type`，运行时常用启发式：`a.length > 1` → `multiple`，否则 → `single`。
**作者不要依赖启发式**：请显式写 `type`，避免判断题/单选题被误判。

### 选项 `o`

- 严格：长度为 2–26，元素必须为字符串；答案须对应其中的大写字母
- 当前内嵌演示库多为 4 或 5 项；不强制 4 选

## 最小合法示例

```json
[
  {
    "chapter": "示例章",
    "section": "示例节",
    "topic": "示例考点",
    "questions": [
      {
        "uid": "demo-q-1",
        "q": "下列不属于企业战略特征的是（ ）。",
        "type": "single",
        "o": ["全局性与复杂性", "稳定性与动态性", "长期性与多样性", "收益性与风险性"],
        "a": ["C"],
        "e": "企业战略一般具有全局性与复杂性、稳定性与动态性、收益性与风险性。"
      },
      {
        "uid": "demo-q-2",
        "q": "属于企业总体战略业务范畴的有（ ）。",
        "type": "multiple",
        "o": ["稳定经营", "改进单一业务单位竞争地位", "抑制某些业务发展", "进入新经营领域", "退出某些业务并重配资源"],
        "a": ["A", "C", "D", "E"],
        "e": "…"
      }
    ]
  }
]
```

```json
[
  {
    "chapter": "示例章",

    "questions": [
      {
        "uid": "case-q-1",

        "a": ["B"],
        "e": "…"
      }
    ]
  }
]
```

## 与学习数据的边界

| 文件/导出 | 用途 | 是否含学习进度 |
|-----------|------|----------------|
| 题库 JSON（分组数组） | 题目内容 | 否（可含 `aiAnalysis` 字段，但是内容不是答题进度） |
| `题库完整学习备份.json`（`format: business-study-backup-v1`） | localStorage + IndexedDB 学习状态 | **是** |

不要用普通题库导出冒充完整学习备份；反之亦然。

## 校验方式

```sh
# 校验内嵌演示题库（从 site/index.html 抽出）
npm run test:schema

# 校验任意外部题库文件
python3 tests/question-bank-schema.py path/to/bank.json

# 只做宽松结构提示（兼容旧字段，不保证判分正确）
python3 tests/question-bank-schema.py --lenient path/to/bank.json
```

JSON Schema 机读副本：`schemas/question-bank.schema.json`（用于编辑器提示；权威行为以本文 + `tests/question-bank-schema.py` 为准）。

## 导入器解析摘要（作者排障用）

页面 `tryParse` 会：去 BOM/注释、去掉 `}` `]` 前尾逗号、必要时自动给单对象或对象序列补上外层 `[]`，再 `JSON.parse`。尾逗号修补正则不识别字符串边界，题干中若含 `,]` 或 `,}` 一类文字，也可能被误改；作者文件应保存为标准 JSON，但当前运行时仍存在此边界，本分支不修改它。
失败时常见文案是「JSON 格式错误，请检查引号和括号」（弯引号/单引号是重灾区）。
`a` 若写成普通字符串，会被按字符拆开——**不要把选项原文或「正确」两字当作答案字符串**。细节与清单见作者指南。

## 仍建议补强的方向（未在本文件强制）

1. 导入 UI 在失败时展示**逐题**错误列表（而不只 toast）。
2. 作者侧一键「下载当前章为 JSON 片段」与「校验后再导入」。
3. 若演示库仍内嵌在 HTML，可继续用章节片段工作流；正式内容请坚持外置 JSON + `test:schema`。
4. 修正运行时的尾逗号正则字符串边界；此项为后续应用改动，不在本分支发布。
