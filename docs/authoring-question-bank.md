# 题库作者指南：如何做出「能导入、能做题」的 JSON

面向非开发作者。本运行时允许你按**章（或节）做成独立题库片段**，再分别导入叠加；每一份片段都必须是**合法 JSON 数组**，并符合 [题库数据约定](question-bank-schema.md)。

## 推荐工作流（构建 → 校验 → 导入）

1. **按章（或按大节）各做一份文件**，例如：
   `第一章-企业战略.json`、`第二章-公司治理.json`
   每份文件顶层都是 `[ ... ]` 数组，里面是若干「题组」。
2. 用本文的模板填写；保存为 **UTF-8**，扩展名 `.json`。
3. **导入前先校验**：
   ```sh
   python3 tests/question-bank-schema.py 第一章-企业战略.json
   ```
   看到 `OK [strict] ...` 再导入。失败时终端会列出第几组第几题的问题。
4. 打开题库学习中心 → **导入** → 选中该 JSON。
   成功提示类似：`导入成功：N 个分组，共 M 题`。
5. 在「章节」下拉里应能看到该章；点开能答题。若提示成功但题目为 0 / 找不到章，见文末排障。

可重复导入多份章节片段；后导入的题会进本地「导入题库」。不要用「完整学习备份」格式去当题库导入。

## 一份「章节片段」长什么样

**顶层必须是数组**（方括号），不是单个对象：

```json
[
  {
    "chapter": "第一章 企业战略与经营决策",
    "section": "第一节 企业战略概述",
    "topic": "考点一：企业战略的内涵",
    "questions": [
      {
        "uid": "ch1-s1-t1-q01",
        "q": "下列不属于企业战略的特征的是（ ）。",
        "type": "single",
        "o": [
          "全局性与复杂性",
          "稳定性与动态性",
          "长期性与多样性",
          "收益性与风险性"
        ],
        "a": ["C"],
        "e": "企业战略一般具有：全局性与复杂性、稳定性与动态性、收益性与风险性。"
      }
    ]
  }
]
```

同一章可以有多组（不同 `section` / `topic`），都放在**同一个**顶层数组里，仍算一份「章节片段」。

严格作者格式用标准英文字段、分组数组、显式题型和大写字母答案数组；中文别名、裸题目数组、字符串答案仅是运行时兼容格式，不通过默认严格校验。`--lenient` 只提供结构提示，不能代替严格校验或人工核对答案。

### 字段速查（作者必填）

| 位置 | 字段 | 怎么写 |
|------|------|--------|
| 组 | `chapter` / `section` / `topic` | 字符串；决定筛选下拉 |
| 组 | `questions` | **非空数组**；一组可多题 |
| 组 | `caseInfo` | 可选；共用材料。**只能是一段文字（或一个对象），不能是数组** |
| 题 | `q` | 题干 |
| 题 | `o` | 选项字符串数组，2–26 个 |
| 题 | `a` | **无重复的大写字母数组**，如 `["C"]`、`["A","D"]`。A=第 1 个选项 |
| 题 | `type` | 必须写：`single` / `multiple` / `judge` |
| 题 | `e` | 解析（推荐） |
| 题 | `uid` | 推荐固定 ID；改题干但想保留错题/解析进度时尤其重要 |

## 导入器实际在做什么（以及「正则」容易坑人的地方）

页面导入会走：`tryParse` → `mergeInto` → `validateCaseGroups`。

### 1）`tryParse` 里的自动修补（看起来像正则魔法）

| 行为 | 含义 | 作者要注意 |
|------|------|------------|
| 去掉 BOM、`//` / `/* */` 注释 | 允许带注释的草稿 | 字符串里的 `//` 一般安全；但不要用奇怪的注释打断结构 |
| 删掉 `}` 或 `]` 前的多余逗号 | 容忍尾逗号 | **不能**修掉所有非法逗号；正则也会误改字符串中的 `,]` / `,}`，需要避免并核对导入后题干；本分支不改此运行时边界 |
| 若不是以 `[` 开头，但像 `{...},{...}` | 自动外包一层 `[]` | 仍须是合法对象序列 |
| 若整段是单个 `{...}` | 自动变成 `[{...}]` | 单个题组对象可以，但**推荐你自己写成数组** |
| `JSON.parse` 失败 | 报错：`JSON 格式错误，请检查引号和括号` | 见下方「最常见挂法」 |

**JSON 只认英文双引号 `"..."`。**
用中文弯引号 `“”`、单引号 `'...'`、Excel/Word 复制来的智能引号 替代 JSON 结构引号 → 会触发「JSON 格式错误」，作者体感就像「怎么都不认 / 正则不过」。题干正文里的中文引号可以保留，不要全文盲目替换。

### 2）答案字段会被「拆成单字符」（高频隐形事故）

若 `a` 写成字符串而不是数组，运行时会：

1. 去掉中文逗号、顿号、分号、空白；
2. **再按每个字符拆开**当成多个答案字母。

因此：

| 你写的 | 实际变成 | 结果 |
|--------|----------|------|
| `"a": ["C"]` | `["C"]` | ✅ 正确 |
| `"a": "C"` | `["C"]` | 运行时兼容；严格校验不接受字符串 |
| `"a": "A、B"` | `["A","B"]` | 运行时兼容；严格校验不接受字符串 |
| `"a": "A,B"` | `["A",",","B"]` | ❌ 英文逗号保留，判分错误 |
| `"a": ["a"]` | `["a"]` | ❌ 不会自动转大写，判分错误 |
| `"a": ["A","A"]` | `["A","A"]` | ❌ 重复答案，无法正确判分 |
| `"a": "正确"` | `["正","确"]` | ❌ 乱码式答案，判题全错 |
| `"a": "全局性与复杂性"` | 每个汉字一个「答案」 | ❌ 完全坏掉 |
| `"a": ["1"]` 或选项下标 | `["1"]` | ❌ 不是 A/B/C |

**铁律：永远写 `"a": ["C"]` 这种无重复的大写字母数组，不要写选项原文。**

### 3）分组 vs 扁平：混用会导致「导入成功但没题」

- **分组格式（推荐）**：元素带 `questions` 数组。
- **扁平格式**：元素本身就是题目（有 `q` / `题干`），导入器会塞进「题库 / 全部题目 / 人工校对」。

判定规则很严：`数组里每一项都像扁平题` 才走扁平；否则整份当分组处理。

因此若你把「章节对象」和「裸题目」混在一个文件里，或章节对象写错成没有 `questions`：

- 可能 **toast 仍显示导入成功**，但该组 `questions` 为空 → **下拉里没有题 / 题数为 0**。

章节片段请统一用分组格式，不要混扁平。

### 4）案例材料

- `caseInfo: ["材料1","材料2"]` → **直接导入失败**（结构错误：多个案例请拆组）。
- 小题里面写 `caseInfo` / `材料` / `背景` / `案例` → 严格校验失败；运行时导入会先丢弃这些字段，可能不报错，但材料会丢失。请上移至组级。
- 有 `caseInfo` 但 `questions` 为空 → **导入失败**。

### 5）和「学习备份」搞混

| 文件 | 特征 | 入口 |
|------|------|------|
| 题库章节 JSON | 顶层 `[...]` 题组 | **导入**按钮 |
| 完整学习备份 | `"format":"business-study-backup-v1"` | **说明与备份 → 恢复完整备份** |

拿备份去「导入题库」，或拿题库去「恢复备份」，都会失败或行为怪异。

## 最常见挂法（对照表）

| 现象 | 常见原因 | 怎么改 |
|------|----------|--------|
| `导入失败：JSON 格式错误，请检查引号和括号` | 弯引号、单引号、缺逗号、多余文字、截断的文件 | 用纯文本编辑器；键名和字符串一律 `"..."`；用校验脚本先跑 |
| `导入失败：题库结构错误：… caseInfo 包含多个案例材料` | `caseInfo` 写成了数组 | 拆成多个题组，每组一段材料 |
| 案例材料导入后不见了 | 写在小题内，被归一化丢弃（不一定报错） | 上移到组级 `caseInfo`；用严格校验提前发现 |
| `导入失败：请粘贴题库文本` | 空文件 | 检查导出是否成功 |
| Toast 成功但题数为 0 / 找不到章 | 分组缺 `questions`、混用扁平、或 `chapter` 写成奇怪结构 | 按模板重写；看 toast 里的「共 M 题」是否为 0 |
| 能看到题但怎么答都错 | `a` 写成了选项原文或中文「正确」 | 改成 `["A"]` / `["B"]` 字母 |
| 单选变成多选或反之 | 没写 `type`，只靠答案个数猜测 | 显式 `"type":"single"` 等 |
| 导入成功但刷新后导入题没了（少见） | 超大带图题库撑爆存储 | 减小图片；看是否提示改用大容量存储，并做完整备份 |

## 排障清单：「我做好的题库上传后不能用」

按顺序做，不要跳步：

1. **确认文件类型**
   - 打开文件第一个非空白字符应是 `[`（数组）。
   - 若看到 `{"format":"business-study-backup-v1"` → 这是学习备份，走错入口。

2. **确认编码与引号**
   - UTF-8 保存。
   - 只把充当键名或字符串边界的错误引号改成英文 `"`；题干内容中的中文引号可保留。不要全文替换，以免破坏正文或转义。

3. **本地校验**
   ```sh
   python3 tests/question-bank-schema.py 你的文件.json
   ```
   - 有报错 → 语法错误按行列号、内容错误按组号/题号改到 `OK`。
   - 若没有 Node/Python 环境，至少把 JSON 粘进 [jsonlint](https://jsonlint.com/) 一类工具确认「纯 JSON 能 parse」。

4. **看导入 toast 原文**
   - `JSON 格式错误…` → 回到步骤 2。
   - `题库结构错误…` → 按文案改 caseInfo / questions。
   - `导入成功：…共 0 题` → 检查每组是否都有非空 `questions`，是否误用扁平混排。

5. **抽一题人工核对**
   - `o` 有几项；`a` 是否为其中的字母。
   - `type` 是否与题干一致（多选必须 `multiple`）。

6. **只导入最小样例验证通道**
   - 先导入仓库里的 `fixtures/question-bank.minimal.valid.json`。
   - 若样例可以、你的文件不行 → 问题在内容格式，不在 App。
   - 若样例也不行 → 继续排查 App/浏览器和导入操作。先导出完整学习备份，再尝试其它浏览器；清除站点数据会删除本地学习记录，不应作为第一步。

7. **分章二分法**
   - 把大文件拆成两个半章再导；看哪一半失败，快速定位坏组。

## 章节片段模板（可复制）

```json
[
  {
    "chapter": "第X章 标题",
    "section": "第X节 标题",
    "topic": "考点：…",
    "questions": [
      {
        "uid": "chX-unique-id-001",
        "q": "题干……（ ）。",
        "type": "single",
        "o": ["选项A内容", "选项B内容", "选项C内容", "选项D内容"],
        "a": ["B"],
        "e": "解析……"
      }
    ]
  }
]
```

多选把 `type` 改成 `multiple`，`a` 写成 `["A","C"]` 这种。

更完整的字段说明、与学习备份的边界、机读 JSON Schema：见 [question-bank-schema.md](question-bank-schema.md)。

## 本分支范围

这些约定和校验器帮助作者提前发现格式错误，不改变已安装应用的导入行为。`site/` 与离线版本 `20261025-pwa2` 保持不变。发现运行时正则或材料丢弃问题时，应另开应用修复并按离线发布流程升级，不把本文描述为已修复运行时。
